# 日本語小説の文章規範（AIくささの除去とリズム設計）

小説の文章規範。AIくさい文（句点過多・メトロノーム文・文末単調・記号の乱発）の診断と修正。

- **優先順位**：作品の文体カルテ（作品ごとに定めた文体規定ファイル）＞ 本規範。**文長・段落の数値はカルテが正本**（カルテの無い作品だけ、下の既定値を使う）
- **機械で測れるもの**（記法・禁止語・段落長・文末の連続・記号量・語の反復）の最終判定は **lint スクリプトに任せられる**（あれば）。本文には、生成のときに効かせる原理を要点で残す（一部は機械でも測れる）

## 1. 文長の波 ── 第0条：短文には、声を乗せる

AIの文は「。」で切る安全運転に流れ、同じ長さの短文が等間隔に並ぶ（メトロノーム文）。正体は**完結できる文を断片で刻むこと**。

> **語り手の声（判断・評価・軽口・自虐）が乗っているなら、短文でも体言止めでも一行段落でもよい。**
> 禁じるのは「無人の観察を刻むこと」。**迷ったら「これは誰が言っているか」を問う。カメラなら繋ぐ。人なら切ってよい。**

- ✗ 無人：「杉の葉ずれ。遠い沢。」　○ 有人：「その、三歩に一度が、悪かった。」
- 感情の名指しを禁じる作品では、声＝**評価・判断・軽口**で出す
- 🔴 落とし穴＝**理屈の飛躍**。決め台詞にする前に「この判断の根拠を一文で言えるか」。言えないなら根拠のほうを書く
- 短文は**決め所専用の弾**（山場・転回・宣告）。平時は因果と観察を一文の中で繋ぎ切る。読点は構文の切れ目にだけ
- **1段落＝一つの観察・動作・判断。**段落末は説明ではなく、人物の選択・発見・数の変化で閉じる。密な説明が続いたら短い確定や軽口で呼吸を変える
- 説明は先にまとめず、**物を使う瞬間や質問への返答に分散**。数字を出したら直後に、その数字で何を判断したかを書く
- **「見た事実 → 推測 → 次の行動」の順を崩さない**
- 余韻の第一手段は**文の切り方と間**。記号（――・……）は第二手段（乱発しない。lint スクリプトがあれば量を機械で見張る）
- カルテの無い作品の既定値＝説明・観察の主体帯40〜70字／段落上限110字

## 1-b. 斜め読みができること

1. 🔴 **一人一呼称**（名前のない人物ほど厳守）。**一語一義**＝同じ物は同じ語で呼び、一つの語を二つの物に使わない
2. 🔴 区別が要る人物にだけ呼び名（役割名でよい）。残りは塊で扱う（視点人物に個別に見えていない人物は、塊で見えているのが正しい）
3. 🔴 **一段落に人物は一人。位置関係を読者に解かせない**（動かせない理由は一つに絞る）
4. 段落の頭に要点を置く。同じ長さの段落を続けない（波）

## 2. 書きながら守る整合の原理

全項目の管理表は作らない。整合は「書き出す前の5行」＋台帳（持ち物・残数・時刻・距離などを記録するメモ）＋事後の点検が受ける。

- **書き出す前に5行**（作品の進行管理メモの「次に書く話」欄へ）：①前話の**締めの一行**（コピーする）②時刻と場所 ③持ち物と残数の増減 ④この話で出す数 ⑤視点人物が新しく知ること。**書き終えたら本文と突き合わせる**
- 状態にない物を使わせない／記録された距離を移動せずに接触させない／時間を巻き戻す場面は**冒頭三行以内**に時間関係を書く
- **確認先のない事実は地の文で断定しない**（数値・設定の機能・現実の物理）。人物の推測として書くか、出さない
- 🔴 高価・希少な資源を使わせるときは**安い代替を列挙**し、使えない理由を一文で書く

## 2-b. 判断文の三点照合

観察を越える**判断・推測・診断・一般論**には——①**根拠**（どの観察から）②**知識経路**（その人物はいつどう知ったか）③**射程**（この人物／この場面／人間一般のどこまで言えるか）。
**一つでも欠ける断定は書かない**（観察だけ残すか「かもしれない」「少なくとも」に狭める）。人物の誤認は「誤認」と記録し、**後の地の文で事実として再利用しない**。

## 3. 会話の括弧規律

**一つの「」＝一人の発話。同一話者の「」を連続させない**（地の文を挟むか、一つの「」に収める）。三人以上の会話では二往復に一度、話者を地の文で指す。

## 4. 駄文テスト

その文で、場面に**新しい行動・知覚・判断**のどれかが加わるか。加わらない文（直前の言い換え・感情の名指し・意味の総括「それは悲しい光景だった」・描写の直後のまとめ直し）は削る（例外＝意図した反復）。

## 5. LLMっぽい表現の禁止

- 空虚な強調語（非常に・まさに・あまりにも・どこまでも）／「〜なのだった」「〜のである」の締め癖
- 🔴 **説明を比喩に逃がさない。**無駄に比喩的な表現を重ねる癖があるため、**何がどうなっているかは直接の言葉で分かりやすく書く**。比喩は少なく、日常の物に例える
- 行為者を主語にする（「〜が感じられた」より、知覚対象か語り手を主語に）

## 6. 場面の進め方

場面の末尾は、**直前の出来事が人物の次の行動を決める**形にする（問題が解決して終わる場面でも、その解決が新しい選択を迫るところまで書く）。言い切りと迷いを織り交ぜる。山場で使う数字や固有の事実を、手前の場面でばらさない。**1話で1つ解決し、1つ新しい選択を迫る。**

## 7. 執筆後の点検

> 🔴 点検は「検出箇所と処置（修正／維持＝理由つき）」が残ったときだけ完了。検出ゼロなら「該当なし」と記録。

1. **機械的点検を回す**（lint スクリプトがあれば）。**NGゼロまで直す**（意図して維持するものは理由を記録して例外にする）
2. **一文構造**＝一文一行に複製し、主述の対応・修飾の掛かり先・省略主語の一意性・誤変換を単独で確認
3. **整合**＝書き出しの5行・台帳と本文を突き合わせる（持ち物・距離・時刻・視点人物の知識）
4. **判断文の三点照合**（§2-b を全件）
5. **会話と場面の通読**＝台詞だけ抜き出し話者名を付けて読む → 移動・受け渡し・時間経過を頭で再現 → 場面ごとに、解決した問題と新しく生じた選択を確認
6. 🔴 **修正したら、差分の前後だけでなく「5行」と、その話で読者が決着を待っている事柄に対して再照合**してから次へ（直した隣を壊すのが最頻の事故）

> ⚠️ ここまでで捕まらないもの（意味の欠陥・書き手の誤った知識）は**別エージェントのレビュー**が受ける（生成した本人に自己採点させない）。
